# 06 · 数据与存档设计

> 本文定义项目的数据资产：客户端存档格式、世界版本迁移链、备份导入导出、
> 服务器房间存档，以及联机共享状态。目标是**数据永不因升级而丢失**。

## 1. 存储层次

```
┌─ 内存（运行时） ──┐   ┌─ 浏览器持久 ─────┐   ┌─ 文件（可携带） ──────┐   ┌─ 服务器 ────────────┐
│ world: Map        │ → │ localStorage      │ → │ 备份 .json / .gz     │   │ server_data/*.json  │
│ trackPieces[] 等  │   │ 'minicraft-cabin- │   │ （手动导出/导入，     │   │ （联机房间世界 +     │
│                  │   │  v3'（自动 60s）   │   │  主机可导入联机图）   │   │  密码/权限，节流落盘）│
└──────────────────┘   └──────────────────┘   └──────────────────────┘   └─────────────────────┘
```

- localStorage 写入失败（隐私模式/容量满）时**降级为内存存档**（`memorySave`），
  界面提示「下载备份可长期保存」——进度在本次会话内不丢。
- 联机时客户端与服务器各存一份；客户端仍是第一权威（主机），服务器房间档用于
  后续加入者快速恢复。

## 2. 客户端存档格式（`buildSaveJson`）

localStorage 键 `minicraft-cabin-v3`，值为单 JSON 对象，顶层 `v:3`。

| 字段组 | 字段 | 说明 |
| --- | --- | --- |
| 世界 | `world: [[key, id]…]` | 稀疏体素表（约 20 万方块量级） |
| 版本 | `worldVersion`（当前 13）、`trackFeatureVersion`（41）、各 `*GrantVersion` | 迁移与特性授权（见 §4） |
| 轨道 | `trackPieces[]`（29 字段/件）、`trackTrain`、`extraTrains[]`、`customTrackTemplates[]` | 完整轨道网与车队、自定义蓝图（≤8×96 件） |
| 家装 | `decorations[]`（≤60）、`decorFloorThemes`、`decorWallThemes`、`savedDecorLayout`、`blockLightStates` | 装修与灯开关 |
| 建筑 | `placedDoors[]`、`buildHistory[]`（≤40） | 玩家放置的门与撤销栈 |
| 玩家 | `player{x,y,z,yaw,pitch}`、`stock`、`chestStock`、`selected`、`hasPickaxe`、`health`、`flying`、`avatarStyle`、`cameraMode/cameraDistance/cameraShoulder` | 位姿与个性化 |
| 进度 | `stats`、`achievements[]`、`storyUnlocked[]`、`storyPage`、`questStage/questDone`、`crystals`、`caveFound/campFound/iglooFound`、`waypoint` | 成就/故事/任务 |
| 世界状态 | `worldTime`、`dayCount`、`raining`、`weatherTimer`、`fireplaceOn`、`gardenReady/gardenTimer`、`fishPopulations[3]`、`mailDay`、`mainDoorExists/doorOpen`、`chestOpened`、`adventureMode` | 环境与开关 |
| 生态 | `cat{…}`、`slimeState[]` | 伙伴与怪物 |
| 设置 | `graphicsMode`、`weatherFx`、`baseFov`、`mouseSensitivity`、`masterVolume`、`trackShapeMode`、`miniMode`、`mapLayer/mapDepth`、`localPlayerName` | 偏好随档保存 |

**加载健壮性**（`loadGame`）：

- `v!==3` 或 `world` 非数组 → 整体拒绝（返回 false，保持现世界）；
- 逐字段防御式解析：轨道/家具/列车等每条记录单独校验数值域与枚举，
  非法项跳过而非崩溃；数值统一 `clamp` 到合法区间；
- 玩家位置若卡进方块 → 传送回门口安全点；
- 成就与故事按状态**重放推导**（防止旧档漏标记）。

## 3. 世界版本迁移链（`worldVersion`）

`loadGame` 按版本号顺序补齐缺失内容（生成函数复用「新世界」同一套，见 02 §6.2）：

| 版本门槛 | 迁移动作 | 背景 |
| --- | --- | --- |
| <2 | `buildCave()` | 补建矿洞 |
| <3 | `buildExpansion(true)` | 扩展东部林地/河流/营地 |
| <4 | `buildFarlands(true)` | 扩展雪原/沙漠 |
| <5 | `buildHouseDetails()` | 小屋内饰 |
| <6 | `buildLargeHouse(true)` | 小屋扩建为 13×14 大屋 |
| <7 | `buildLoft()` | 阁楼 |
| <8 | `buildCatCorner()` | 猫角 |
| <9 | `buildMailbox()` | 信箱 |
| <10 | `buildGroundDepth()` | 地下 10 层 |
| <11 | `seedUndergroundOres()` | 地下补矿 |
| <13 | `migrateWorld128Deep()` | **64→128 扩张 + 深层世界**：补外域地表/地下、两大水域、延伸道路、拆旧树篱 |

迁移原则：

- **只增不改**：玩家已修改的方块永不覆盖（`if (!get(...)) set(...)` 模式）；
- **确定性**：外域地貌由坐标哈希决定，与时间/随机数无关；
- **双端一致**：`server.py` 的 `_migrate_legacy_world()` 是同一算法的 Python 复刻
  （含相同的 `undergroundDepthType/outer_hash` 哈希常数），保证同一存档在浏览器与
  服务器迁移后**逐方块一致**（回归测试断言具体坐标）。

## 4. 特性授权版本（`*GrantVersion`）

用于「一次性补发」历史存档缺失的资源/行为，避免重复发放：

| 字段 | 当前值 | 语义 |
| --- | --- | --- |
| `woodGrantVersion` | 1 | ≠1 → 木板保底 1000 |
| `allItemsGrantVersion` | 4 | ≠4 → 全部物品保底 1000 |
| `creatureDefaultVersion` | 1 | =1 时才读取 `adventureMode`，否则强制 false（旧档默认和平） |
| `cameraDefaultVersion` | 1 | =1 时才读取 `cameraMode`，否则默认第三人称 |

## 5. 备份导入导出

### 5.1 导出（`exportSave`）

1. `flushSave()` 生成完整 JSON；
2. 尝试 `CompressionStream('gzip')` 压缩，**小于原始体积才采用**；
3. 下载为 `minicraft-backup-day-{N}.json` 或 `minicraft-backup-day-{N}.minicraft.gz`，
   面板显示体积对比。

### 5.2 导入（`importSaveFile`）

```
读文件（自动识别 gzip 魔数 1f 8b 并解压）
  → validateBackupText：
      · 非空 JSON、顶层 v===3、world 为数组
      · world ≤300,000 条；抽样前 200 条校验 [str, number] 形状
  → 先快照当前世界（previous）
  → loadGame(text)；失败/异常 → 回滚 previous，提示「原世界未被替换」
  → 成功：断开联机（避免旧状态外溢）、worldGeneration++（使挂起的异步成就失效）、
        全量刷新 UI 与网格
```

### 5.3 联机主机导入地图（`importNetworkMapFile`）

仅联机主机可用：用备份覆盖当前世界 → 应用 shared 状态 → 广播 `snapshot` 给全房间。
失败时同样回滚且**联机世界不被替换**。房间聊天出现系统公告。

## 6. 服务器房间存档

`server_data/{room}.json`：

```json
{
  "world":  {"x,y,z": blockId, …},
  "shared": {"worldVersion": 13, "trackPieces": [...], "cat": {...}, …},
  "password_hash": "<sha256 hex 或空串>",
  "guest_can_build": true,
  "updated": 1786369520.19
}
```

- 写入时机：脏数据节流（60s 静默或 60s 脏，0.5s 轮询）+ 应用退出 flush；
- 原子写：先 `.tmp` 再 `os.replace`；
- `shared` 与客户端 `sharedNetworkState()` 的字段同构（见 §7），
  服务器只透传不解释（除权限/密码/环境字段剥离）。

## 7. 联机共享状态（`sharedNetworkState`）

主机每 1Hz（或变更后 180ms 防抖）广播的结构化状态，也是 snapshot 的主体：

| 字段 | 内容 |
| --- | --- |
| `worldVersion / worldWidth / undergroundDepth` | 世界元数据（13 / 128 / 10） |
| `trackPieces[]`、`trackTrain`、`extraTrains[]` | 轨道网与车队全量 |
| `decorations[]`、主题、`blockLightStates`、`placedDoors` | 家装状态 |
| `mainDoorExists / doorOpen / fireplaceOn / chestOpened` | 小屋开关 |
| `gardenReady / gardenTimer / fishPopulations` | 生活系统 |
| `worldTime / dayCount / raining / weatherTimer / adventureMode` | 环境（服务器只认 host 来源） |
| `cat{…}` | 伙伴猫 |

guest 应用时走 `applyNetworkShared()`：逐集合**整体替换** + 数值清洗 + 重建索引，
随后 45ms 防抖重建网格。猫的指令有 2.5s「本地优先窗口」（`catCommandPendingUntil`），
避免自己下的指令被 1Hz 广播回滚产生抖动。

## 8. 数据安全清单

| 风险 | 缓解 |
| --- | --- |
| localStorage 不可用 | 降级内存存档 + 提示导出 |
| 存档解析异常 | try/catch 整体回退 + 逐字段防御解析 |
| 导入恶意/损坏备份 | 版本/体量/抽样三重校验 + 失败回滚 |
| 服务器半写文件 | tmp + 原子替换 |
| 联机数据竞争 | `netApplying/netSuppress` 防回环；环境字段 host-only；checksum 自愈 |
| 旧版本升级丢世界 | 版本迁移链 + 特性授权 + 双端一致算法 |
| 异步成就跨世界串扰 | `worldGeneration` 代数标记（重置/导入后使旧 setTimeout 失效） |
